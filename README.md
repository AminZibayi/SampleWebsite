# راهنمای معماری سامانه فروشگاهی و تحریریه مهندسی
## مرجع آموزشی توسعه نرم‌افزار فرانت‌اند با استاندارد خالص HTML5 ،CSS3 و Modern ES6+ JavaScript

این مخزن یک پروژهٔ نمونهٔ سازمانی و ماژولار است که **بدون استفاده از حتی یک خط فریم‌ورک خارجی (صفر ری‌اکت، ویو، انگیولار یا بوت‌استرپ)** پیاده‌سازی شده است. هدف بنیادین این پروژه، **آموزش عملی الگوهای طراحی GoF، تفکیک دغدغه‌ها (SoC)، رندرینگ بهینهٔ DOM و تایپ‌سیفتی بومی در جاوااسکریپت** به دانشجویان و مهندسان وب است.

---

## ۱. نقشه راه یادگیری و الگوهای طراحی پیاده‌شده (Design Patterns)

کدهای این پروژه به گونه‌ای معماری شده‌اند که هر لایه پاسخگوی یک نیاز ساختاری مشخص باشد:

```text
src/
├── core/                   # هسته مرکزی و الگوهای زیرساختی
│   ├── EventBus.js         # Observer / Pub-Sub Pattern (ارتباط سست و غیرمستقیم ماژول‌ها)
│   ├── Store.js            # Proxy Pattern + Observer (مدیریت حالت واکنش‌گرا بدون Virtual DOM)
│   ├── Router.js           # Strategy & Middleware Pattern (مسیریاب SPA با Route Guards)
│   └── Component.js        # Template Method Pattern (چرخه حیات قطعی و مدیریت نشت حافظه)
├── services/               # لایه دامنه و مخازن داده (Repository & Service Layer)
│   ├── StorageService.js   # Adapter / Gateway Pattern (عایق‌بندی localStorage و خطایابی سهمیه)
│   ├── AuthService.js      # RBAC / Identity Provider (شبیه‌ساز نشست و کنترل دسترسی ادمین/مشتری)
│   ├── ProductService.js   # Repository Pattern (فیلترینگ چندمعیاره، مرتب‌سازی و عملیات CRUD)
│   ├── OrderService.js     # Transaction Script (مدیریت سبد، کدهای تخفیف و صدور فاکتور)
│   ├── ArticleService.js   # Content Query Aggregator (سرمقاله، تخمین زمان مطالعه و ارجاع متقابل)
│   └── FeedbackService.js  # Append-Only Ledger (دریافت انتقادات فوتر و بازبینی در پنل مدیر)
├── utils/                  # توابع خالص و ابزارهای بهینه‌سازی
│   ├── dom.js              # XSS Prevention, DocumentFragment & WAI-ARIA Focus Trap
│   ├── debounce.js         # Higher-Order Function / Decorator Pattern (بهینه‌سازی تایپ کاربر)
│   ├── formatters.js       # Internationalization (اعداد فارسی، واحد تومان و تقویم شمسی جلالی)
│   └── validators.js       # Pure Predicates (الگوریتم استاندارد لونا برای شماره کارت و موبایل ایران)
├── data/
│   └── seed.js             # Seed Repository (داده‌های پیش‌فرض تعیین‌کننده و ایزوله)
└── views/                  # لایه نمایش و واسط کاربر
    ├── components/         # کامپوننت‌های قاب و پوسته‌ای (Header, Footer, CartDrawer, Modal, Toast)
    └── pages/              # صفحات SPA متناظر با مسیرهای Hash
```

### ۱.۱. الگوی Proxy + Observer (واکنش‌گرایی بدون Virtual DOM سنگین)
* **فایل:** `src/js/core/Store.js` و `src/js/core/EventBus.js`
* **چرا؟** فریم‌ورک‌های سنگین با بازتولید درخت مجازی DOM و الگوریتم Reconcile هزینه‌های محاسباتی پردازنده را افزایش می‌دهند. در این پروژه با استفاده از تلهٔ `set` در `Proxy` استاندارد ES6، هرگونه انتساب به متغیرهای حالت (`store.state.cartOpen = true`) بی‌درنگ رهگیری شده و رویدادی مجزا (`state:cartOpen`) از طریق `EventBus` ساطع می‌شود. کامپوننت‌ها به جای نقاشی مجدد کل صفحه، صرفاً بخش‌های هدف خود را بازنویسی می‌کنند.

### ۱.۲. الگوی Template Method در چرخه حیات کامپوننت
* **فایل:** `src/js/core/Component.js`
* **چرا؟** وب‌اپلیکیشن‌های بدون فریم‌ورک در معرض نشت حافظه (Memory Leaks) قرار دارند (رویدادهایی که پس از حذف المان همچنان در حافظه فعال می‌مانند). کلاس پایه `Component` ساختاری قطعی شامل `render()`، `mount()`، `bindEvents()` و `destroy()` تعریف می‌کند. متد `listen()` به صورت خودکار گوش‌به‌زنگ‌های ثبت‌شده را جمع‌آوری کرده و در هنگام خروج صفحه از دید کاربر، آنها را از حافظه آزاد می‌سازد.

### ۱.۳. الگوی Event Delegation (بهینه‌سازی کارایی رندر DOM)
* **فایل:** `src/js/views/pages/StorefrontPage.js` و `src/js/views/components/CartDrawer.js`
* **چرا؟** در روش‌های غیرحرفه‌ای، به ازای هر کارت محصول در صفحه چندین شنونده `addEventListener` متصل می‌شود (مثلاً ۲۰ کارت × ۳ دکمه = ۶۰ لیسنر). در این پروژه با تکیه بر خاصیت حباب‌زنی رویدادها (Event Bubbling)، تنها یک شنونده در کانتینر والد ثبت شده و به کمک `e.target.closest('[data-act]')` هویت عملیات شناسایی می‌گردد.

### ۱.۴. الگوی Repository & Service Layer (شبیه‌سازی ارتباط با شبکه)
* **فایل:** `src/js/services/ProductService.js` و `StorageService.js`
* **چرا؟** لایهٔ نمایش هرگز نباید بداند داده‌ها در `localStorage` ذخیره شده‌اند یا از یک وب‌سرویس RESTful دریافت می‌شوند. تمامی توابع سرویس به شکل ناهمگام (`Promise`) همراه با شبیه‌سازی تاخیر واقعی شبکه (`sleep(150, 300)`) عمل می‌کنند تا اسکلت‌های پیش‌بارگذار (Skeleton Loaders) و حالت‌های خطا به درستی دیده شوند.

### ۱.۵. الگوی Strategy & Middleware در مسیریاب کلاینت (Router Guards)
* **فایل:** `src/js/core/Router.js`
* **چرا؟** دسترسی به مسیرهای حساسی چون `#/admin` یا `#/checkout` نباید در تک‌تک صفحات با کدهای تکراری بررسی شود. مسیریاب بر پایه زنجیرهٔ گاردها (Middleware Guards) طراحی شده و در صورت عدم برقراری شرط احراز هویت یا سطح دسترسی نقش ادمین، کاربر را به `#/login` هدایت کرده و رویداد اخطار منع دسترسی به سیستم اعلان (Toast) ارسال می‌کند.

## ۲. طراحی بصری و استانداردهای بومی راست‌چین (RTL & Bento-Grid)

1. **دایرکشن و تایپوگرافی بومی:** تمامی المان‌ها با جهت‌گیری کامل راست به چپ (`dir="rtl"` و `lang="fa-IR"`) همراه با فونت استاندارد **وزیرمتن (Vazirmatn)** و فعال‌سازی `font-variant-numeric: tabular-nums` پیکربندی شده‌اند.
2. **استفاده از خواص منطقی CSS (Logical Properties):**
   - به جای تعاریف ایستا مانند `margin-left` یا `padding-right`، منحصراً از خواص منطقی نظیر `margin-inline-start`، `padding-block`، `inset-inline-end` و `border-inline-start` استفاده شده تا بدون وابستگی به قوانین شکننده، چیدمان RTL کامل و بدون نقصی ارائه شود.
3. **معماری لایه‌ای CUBE CSS / ITCSS با `@layer` بومی:**
   - ساختار استایل‌ها به لایه‌های استاندارد تفکیک شده است:
     `@layer reset, tokens, base, layout, components, utilities;`
     این امر بدون نیاز به پیش‌پردازنده‌ها (Sass/Less)، تداخل تقدم و اولویت سلکتورها (CSS Specificity Wars) را حل می‌کند.
4. **سیستم تم‌گذاری دوگانه (Light & Dark Theme):**
   - متغیرهای طراحی (CSS Custom Properties) متناسب با تم تیره و روشن تعریف شده و انتخاب کاربر در `localStorage` ماندگار می‌گردد و از `prefers-color-scheme` سیستم‌عامل کاربر نیز پشتیبانی می‌کند.

## ۳. امنیت در کلاینت و دسترس‌پذیری (Security & a11y)

1. **مهار آسیب‌پذیری‌های XSS:**
   - استفاده از متدهای ایمن DOM (`textContent` و تابع اختصاصی `escapeHtml`) مانع از تزریق اسکریپت‌های مخرب از طریق فیلدهای جستجو، فرم بازخوردها یا توضیحات محصولات می‌شود.
2. **تله‌گذاری فوکوس کیبورد (Focus Trapping):**
   - پنجره‌های مودال و منوی کشویی سبد خرید از استاندارد WAI-ARIA Dialog تبعیت می‌کنند:
     کلید `Escape` پنجره‌ها را می‌بندد و کلید `Tab` فوکوس را داخل دیالوگ حفظ می‌کند تا کاربران کم‌توان و کاربران کیبورد بتوانند بدون سردرگمی با سایت کار کنند.
3. **اعتبارسنجی الگوریتم لونا (Luhn Algorithm):**
   - فرم پرداخت شبیه‌ساز شاپرک مجهز به چک‌سام استاندارد لونا است تا از ورود شماره کارت‌های تصادفی نامعتبر جلوگیری شود.

## ۴. راه‌اندازی و اجرای ابزارهای تضمین کیفیت (Tooling & Linters)

کدها بدون نیاز به کامپایل TypeScript نوشته شده‌اند، اما به کمک **JSDoc جامع و پیکربندی سخت‌گیرانهٔ `jsconfig.json`** تایپ‌چک کامل روی آن‌ها اجرا می‌شود:

```bash
# نصب پکیج‌های توسعه و ابزارهای تحلیل ایستای کد
npm install

# اعتبارسنجی تایپ‌ها بدون نیاز به بیلد یا بیلد تولز
npm run typecheck

# بررسی قوانین کیفی جاوااسکریپت با ESLint Flat Config
npm run lint:js

# کنترل ساختار استایل‌ها و قوانین خواص منطقی RTL با Stylelint
npm run lint:css

# کنترل ساختار و دسترس‌پذیری نشانه‌گذاری HTML5 با HTMLHint
npm run lint:html

# باز کردن سایت در مرورگر با یک سرور استاتیک ساده
npx serve .
# یا به کمک پایتون:
python -m http.server 4173
```

## ۵. ویژگی‌ها و سناریوهای کاربری قابل بررسی در سایت

- **ویترین و صفحه اصلی:** بنر قهرمان Bento Grid، فیلتر آنی دسته‌ها، اسلایدر تعیین سقف قیمت، سوئیچ کالاهای موجود و مرتب‌سازی چندگانه.
- **سبد خرید و درگاه پرداخت شاپرک (`#/gateway`):** منوی کشویی واکنش‌گرا با استپرهای کاهش و افزایش موجودی، درج کد تخفیف `LEARN10` (۱۰٪ کسر)، شماره کارت با فرمت‌دهی خودکار ۴ رقمی، شمارنده معکوس نشست ۱۰ دقیقه‌ای، دکمهٔ دریافت رمز دوم پویا (با کول‌داون ۱۲۰ ثانیه و پیامک از طریق Toast) و صدور فاکتور رسمی قابل چاپ با شماره رهگیری یکتا.
- **احراز هویت دوگانه (`#/login`):** دکمه‌های «ورود سریع ۱-کلیکه» برای شبیه‌سازی ورود به عنوان **مدیر سیستم** و **مشتری نمونه**.
- **پنل مدیریت سیستم (`#/admin`):** مدیریت کامل اقلام کاتالوگ (افزودن، ویرایش قیمت و موجودی، حذف با هماهنگی آنی با ویترین)، بازرسی وضعیت سفارش‌های مشتریان و صندوق پیام‌های نقد و پیشنهادات ارسال‌شده از فوتر.
- **بخش تحریریه و مجله (`#/articles`):** فیلتر بر اساس تگ‌های تخصصی، نمایش زمان تخمینی مطالعه، فهرست مطالب خودکار (TOC) برگرفته از سرتیترهای مقاله، و ابزارک ارجاع و خرید مستقیم محصولات بررسی‌شده در متن.
- **صندوق بازخورد در فوتر:** ارسال نقد و امتیاز که بلافاصله بدون رفرش صفحه به پنل مدیریت منتقل می‌شود.
